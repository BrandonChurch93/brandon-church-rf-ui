# RainFocus UI Challenge · Brandon Church

## What this is

A pixel-faithful build of the provided Figma page ("Event setup guide") in React and hand-written SCSS, responsive down to 320 px. The original design is what loads. A pill at the bottom right opens Brandon's Mode, an optional extra that reimagines the same page as a working event admin application. Brandon's Mode never changes how the original design renders.

## Open without building

Unzip and open `build/index.html` in a browser. No server or install needed.

## Run locally

Prerequisites: Node 20.19 or later, or 22.12 or later (see `engines` in `package.json`).

```
npm install
npm run dev       # development server
npm run build     # writes build/ (a single self-contained index.html)
npm run preview   # serves build/
```

The build is static and deploys to any static host. Routing uses the URL hash, so no rewrites are needed. `vercel.json` is included.

## Project structure

```
src/
  faithful/   the Figma recreation: one page, hand-rolled SCSS, no libraries
  app/        the stage, the mode pill and the transition between the two modes
  motion/     GSAP timelines and motion tokens shared by the transition and lists
  paper/      Brandon's Mode: shell, views, UI primitives, hooks
  store/      Zustand store with persistence, slices per feature, selectors
  data/       seed data for three demo events (generated by scripts/generate-seed.mjs)
  styles/     tokens, mixins and global styles for both modes
tests/
  e2e/        Playwright behavior tests
  gates/      pixel, accessibility, motion and file:// build gates
  visual/     screenshot catalog for review
```

## Design fidelity notes

- Fonts: Inter, self-hosted and inlined in the build. It is the same file the design uses.
- Assets: icons and images exported from the Figma file, in `src/assets/`.
- Tokens: every color, size and spacing value for the original design lives in `src/styles/faithful-tokens.scss`, so a live edit is one line. Brandon's Mode tokens are in `src/styles/tokens.scss`.
- Responsive interpretation: the design is desktop only. Below 900 px the navigation becomes a drawer behind a menu button; below 600 px the content stacks into a single column.
- The build is checked against a reference render of the design at 1447, 1024, 768, 390 and 320 px (`tests/gates/faithful.spec.ts`).

## Brandon's Mode

Every navigation item leads to a working view: the setup guide, attendees, attendee types, packages, registration codes, discounts, content (an agenda you can drag sessions around) and exhibitors (cards and an interactive floor map). It has light and dark themes, a mobile layout with bottom tabs and bottom sheets, keyboard support throughout, undo for destructive actions, and three demo events to switch between. Press Cmd+K (Ctrl+K on Windows) for the command palette. Data is stored in your browser only (localStorage); "Reset demo data" in the account menu restores the original data.

## Testing

Install first: `npm install` and `npx playwright install chromium webkit`. Then `npm run verify` runs, in order:

- typecheck: TypeScript strict, app and tooling
- lint: ESLint with accessibility rules, zero warnings
- build: the single-file production build
- e2e: Playwright behavior tests in Chromium, plus a smoke test in WebKit
- gate:faithful: pixel comparison of the original design against the reference render
- gate:a11y: axe audits of both modes, both themes, desktop and mobile, with layers open
- gate:motion: the mode transition's timing and main-thread long tasks
- gate:build: opens `build/index.html` over file:// in Chromium and WebKit
- visual: regenerates the screenshot catalog in `tests/visual/__captures__/`
